## 1. Purpose
- A **DSR** is a person of the distributor who books or delivers (DSR Type 0001 - Order Booker by default; Delivery Men are DSRs too) [observed 2026-10-05]. Every PJP names one DSR (see pjp.md), so a DSR must exist and be mapped to the distributor before a PJP can be created for him [observed 2026-10-09; order of group 66 seq 17-19, 25].
- Place in the business: master data before the Daily Cycle; set up by group 66 between the outlet/section setup and the PJP setup.

## 2. Actors and roles
- **DT path:** the Maker (Auto_Multi_Orga) creates the DSR on **DSR Profile - DT** and Forwards it; the Checker (Auto_Tssm) approves on **DSR Approval** with one Forward [observed 2026-10-05].
- **HQ path:** the HQ user (headquarter) creates the DSR on **DSR Profile HQ** and Forwards it [observed 2026-10-09]; the HQ-created DSR needs **no approval** before it is used on a PJP [stated 2026-10-09 Syed Kamran].
- **Change track:** the Maker saves and Forwards a change request; the Checker approves it with one Forward **on the same screen** (there is no separate "...Approval" menu item for DSR change tracks) [observed 2026-10-09].

## 3. Documents and master data
- **DSR**: DSR Code typed by the user and stored upper-case (Auto241134 -> AUTO241134; AUTOH24109); not generated by the app [observed 2026-10-05, 2026-10-09].
- Group 66 records on cnr1dev1: **AUTO241134** (DT, name AutomationQ, renamed Auto_Test241134 by request 48, User ID Auto_Tssm, CNIC 12026-2241134-0 changed to 12026-2241134-1 by request 40) and **AUTOH24109** (HQ, name Auto_OB, User ID Auto_Multi_Orga, CNIC 12026-2410090-1) [observed 2026-10-05, 2026-10-09]; AUTOH24109 with User ID Auto_Multi_Orga is acceptable [stated 2026-10-09 Syed Kamran].
- **DSR change request** (Change Track DSR Profile): request number (48), description = old DSR name, distributor, status, request date [observed 2026-10-09].
- **DSR document change request** (Change Track DSR Document): request number (40), description = DSR code [observed 2026-10-09].

## 5. Process: the business steps in order
A. DSR created by the distributor (group 66 seq 17-18)
1. [Maker] Navigate to DSR Profile - DT; Enter DSR Code (a real click before typing), name, type, employee no, hierarchy, dates, vehicle, user, designation; Click Save -> "Saved successfully" [observed 2026-10-05] (66:17:00560001).
2. [Maker] Fill Address > Residence; Click Save -> "Saved successfully"; add Documents (CNIC), Qualification, Previous Experience, Device rows, each row Save -> "Record Saved Successfully!" [observed 2026-10-05].
3. [Maker] Click Forward; Enter comment; Save -> "Forwarded successfully" [observed 2026-10-05].
4. [Checker] Navigate to DSR Approval; open the DSR (second click); Click Forward; comment; Save -> "Forwarded successfully"; the pending list empties (one Checker step) [observed 2026-10-05] (66:18:00390001).

B. Change the DSR's name / status (seq 21-22)
1. [Maker] Navigate to Change Track DSR Profile; pick the DSR in "List of DSR"; Enter New Value for DSR Name (and Status); Click Save -> "Saved successfully", request 48 (In-Active) [observed 2026-10-09] (66:21:00250001).
2. [Maker] Select the request (first click selects); Click Forward; comment; Save -> "Forwarded successfully" [observed 2026-10-09].
3. [Checker] Same screen; select the request; Click Forward; comment; Save -> "Forwarded successfully"; after re-opening: request Active and the DSR renamed (AutomationQ -> Auto_Test241134) [observed 2026-10-09] (66:22:02240001).

C. Change the DSR's document (seq 23-24)
1. [Maker] Navigate to Change Track DSR Document; pick the DSR; Enter New Value CNIC and the new number (typed digit by digit); Click Save -> "Saved successfully", request 40 [observed 2026-10-09] (66:23:01320001).
2. [Maker] Select the request; Click Forward; comment; Save -> "Forwarded successfully" [observed 2026-10-09].
3. [Checker] Same screen; select the request; Click Forward; comment; Save -> "Forwarded successfully"; after re-opening: request Active, CNIC 12026-2241134-0 -> 12026-2241134-1 [observed 2026-10-09] (66:24:02250001).

D. DSR created by HQ (seq 33-34)
1. [HQ user] Navigate to DSR Profile HQ; fill as in A (plus Report To); pick a User ID not tied to another DSR; Click Save -> "Saved successfully" (status stays In-Active) [observed 2026-10-09] (66:33:01220001).
2. [HQ user] Address (unique cell numbers), Document, Qualification, Previous Experience, Device; Click Forward -> "Forwarded successfully" [observed 2026-10-09].
3. [HQ user] Navigate to Distributor Mapping; distributor row; DSR sub-tab; tick the DSR; Save (no toast) [observed 2026-10-09] (66:34:02460001). No approval needed before the PJP [stated 2026-10-09 Syed Kamran].

## 8. Rules and validations
- **One login user per DSR**: saving a DSR whose User ID is already tied to another DSR is refused with "User associated with Other DSR(s): <DSR name>"; nothing is saved [observed 2026-10-09].
- **DSR cell numbers are unique**: a cell number used by another DSR is refused with "Duplicate DSR Cell number entered: <distributor>~<DSR code>~<DSR name>" [observed 2026-10-09]. (Previous Experience phone numbers are not checked [observed 2026-10-09].)
- **CNIC is a 13-digit mask #####-#######-#** (format like 85420-0524526-5 [stated 2026-10-05 Syed Kamran]); a number that does not fit is refused with "Document Number-Value is Not According to the Format" [observed 2026-10-05]. The masked field needs the digits typed one by one from the start [observed 2026-10-09].
- DSR Code is typed by the user and upper-cased; the workbook code was free (no duplicate message seen) [observed 2026-10-05].
- Vehicle: the DT DSR got vehicle 999713312 - Automation151825 (a vehicle of an earlier run; the vehicle created that day, 999713523, was not used) [observed 2026-10-05]; on HQ the workbook vehicle "0041 - Automation261218" was offered and used (noted in the log as "works here, unlike DT") [observed 2026-10-09].
- Change Track DSR Profile has only DSR Name and Status as changeable attributes (no DSR Type) [observed 2026-10-09].
- Change Track DSR Document offers only document type CNIC [observed 2026-10-09].
- Forward on a change request is active only after the request row is selected [observed 2026-10-09].
- Grids are not refreshed after Forward: re-open the screen (leave to another screen and back) before reading the status [observed 2026-10-09].
